# T2(v2): 한국어 식품명만으로 초가공식품을 가려낼 수 있는가

국민건강영양조사 2019-2022년 24시간 회상 자료의 식품코드를 **식품명·제품명·제조사·식품군 정보만으로** NOVA 4군(특히 초가공식품 여부)으로 자동 분류할 수 있는지 평가한다. 규칙 기반, 텍스트 머신러닝, 로컬 대형언어모델(LLM)을 팀의 2인 합의 정답셋과 비교하고, 분류 오류가 성인의 초가공식품 에너지 비율(UPF%) 추정을 얼마나 바꾸는지 본다.

v1(초가공식품 섭취와 대사 위험)에서 계획한 2인 NOVA 배정이 이번 연구의 **정답셋**이 된다. 배정 작업은 그대로 쓰인다.

> **순서 규칙(중요)**
> 1. `code/SAP_prespecified.md`를 팀이 검토·수정하고 날짜를 적어 확정한다.
> 2. 두 사람이 정답셋을 독립 배정하고 kappa를 계산한 뒤 합의한다.
> 3. 그다음에만 `run_all.sh classify`와 `evaluate`를 실행한다.
>
> 분류기 결과를 본 뒤 정답을 고치거나, 규칙·프롬프트·few-shot 예시·성공 기준을 바꾸면 안 된다. 바꿔야 하면 SAP의 `변경 기록`에 날짜와 이유를 적고 논문에 밝힌다.

## 2. 환경 설치 (한 번만)

공용 `dh` 환경은 다른 팀도 쓰므로 건드리지 않는다. LLM용 환경을 따로 만든다.

```
conda env create -f environment-llm.yml     # 저장소 최상위에서 실행
conda activate dh-llm
# 모델 내려받기(약 15GB, 14B는 약 30GB 추가). 캐시 위치를 바꾸려면 HF_HOME 지정
python -c \
  "from huggingface_hub import snapshot_download as d; d('Qwen/Qwen2.5-7B-Instruct')"
```

- 연구실 서버에 이미 `dh-llm` 환경과 모델 캐시가 있으면 그대로 쓴다.
- 외부 LLM API는 쓰지 않는다. 모델에는 식품코드 사전 문자열만 들어가며 응답자 단위 자료는 넣지 않는다.
- 원고 변환(`md2docx.py`)은 기존 `dh` 환경의 파이썬으로 실행한다.

## 3. 실행 방법

```
cd code
bash run_all.sh prepare          # 1-3단계 (약 10초)
# → SAP 확정 → results/gold_rater_A.csv, gold_rater_B.csv 독립 배정 (4절)
bash run_all.sh kappa            # 4단계 → 합의 → results/gold_labels.csv 저장
nvidia-smi                       # 사용 중이지 않은 GPU 번호 확인 (다른 사용자가 쓰는 GPU 금지)
CUDA_VISIBLE_DEVICES=0 bash run_all.sh all    # 5-10단계 (규칙·ML 약 30초, LLM 7B 약 3분)
```

- 출력 위치는 기본 `../results`, `../figures`이며 `T2_RESULTS_DIR`, `T2_FIGURES_DIR`로 바꿀 수 있다.
- 14B 모델도 돌리려면 `T2_LLM_MODELS=Qwen/Qwen2.5-7B-Instruct,Qwen/Qwen2.5-14B-Instruct`를 지정한다(탐색 분석).
- 난수 시드는 `config.SEED`로 고정했다. LLM은 샘플링 없이 로짓 최댓값을 쓰므로 같은 GPU·라이브러리 버전에서 결과가 같다.
- CPU 스레드는 16개로 제한되어 있다(`run_all.sh`). 스레드 제한 없이 06단계를 돌리면 매우 느려질 수 있다.
- `gold_rater_A/B.csv`가 이미 있으면 03단계가 덮어쓰지 않는다.
- 정답 파일 열: `N_FCODE, nova, uncertain, stratum, 에너지비율_pct` (합의 초안 `gold_consensus_draft.csv`에서 빈칸을 채워 저장하면 된다).

## 4. 정답 배정 프로토콜

### 4.1 배정 단위와 대상

- 단위는 식품코드(`N_FCODE`)다. 2019-2022년은 코드 체계가 같아 한 번만 배정한다.
- 대상은 `03_sample_gold.py`가 고른 400개다(에너지 상위 200개 전수 + 나머지에서 식품군 비례 무작위 200개). 템플릿은 순서를 무작위로 섞었다.
- 참고 열: `식품명`, `식품군명`, `대표_제품명`, `대표_제조사`, `제품정보_기재비율`, `대표_응답식품명`, `대표_음식명`. 필요하면 제품 포장·온라인 원재료명을 찾아보고 출처를 `note`에 적는다.
- 분류기 예측 파일(`results/predictions/`)은 배정과 합의가 끝날 때까지 만들지도 보지도 않는다.

### 4.2 NOVA 정의 (Monteiro 등, 2019)

1. 비가공·최소가공: 세척·절단·건조·냉동·삶기·분쇄·살균 등 물리적 처리만 한 식품
2. 가공 요리재료: 설탕·물엿·꿀·식용유·버터·소금·식초·전분 등 1군에서 추출·정제한 재료
3. 가공식품: 1군에 2군을 더해 절임·염장·발효·통조림 등 전통 방법으로 만든 단순 제품
4. 초가공식품: 산업용 원료·첨가물(향료·색소·유화제·감미료·가공전분 등)로 만든 즉석 섭취 제품

### 4.3 결정 규칙 (템플릿 `rule` 열에 D 번호 기록)

SAP 3.2의 D1-D10과 같다. 팀이 SAP를 확정할 때 바꿀 수 있지만, **바꾸면 `prompts.py`의 추가 규칙도 똑같이 바꿔야** 사람과 LLM이 같은 지침을 받는다(정답 배정 전에만).

- D1 물리적 처리만 → 1군 (쌀·밀가루·건조 파스타·생고기·우유·무가당 플레인 요구르트·원두커피·100% 주스)
- D2 추출·정제 요리재료 → 2군
- D3 전통적 절임·염장·발효·통조림 → 3군 (김치·젓갈·재래 장류·두부·떡·국수·조미김·자연치즈·잼·발효주)
- D4 첨가물이 든 즉석 제품 → 4군 (라면·과자·양산빵·가공육·어묵·탄산·가당음료·가공우유·믹스커피·소스류)
- D5 증류주(희석식 소주 등)·증류주 기반 혼성주 → 4군
- D6 빵·케이크·도넛 → 4군
- D7 조리 음식 코드 → 주재료 가공도. 제품명이 주로 레토르트·냉동 제품이면 4군 + uncertain=1
- D8 시판 개량 고추장·된장·양조간장 → 3군 + uncertain=1, 쌈장·초고추장·춘장·혼합간장 → 4군
- D9 제품 코드는 대표 제품의 원재료로 판단, 확인이 어려우면 가장 가능성 높은 군 + uncertain=1
- D10 빈칸 금지

### 4.4 절차

1. **보정 연습**: `practice_codes.csv`(정답셋 밖 30개)를 함께 배정하며 규칙 해석을 맞춘다. kappa에 넣지 않는다.
2. **독립 배정**: A는 `gold_rater_A.csv`, B는 `gold_rater_B.csv`만 채운다. 끝날 때까지 서로 보거나 상의하지 않는다.
3. **kappa**: `bash run_all.sh kappa`. 합의 전 값(4범주, 초가공 여부, 층별)을 그대로 논문에 보고한다.
4. **합의**: `rater_disagreements.csv`를 에너지 비율 순으로 보며 근거를 비교해 정한다. 합의가 안 되면 교수가 결정하고 uncertain=1로 둔다.
5. **저장**: `gold_consensus_draft.csv`의 빈칸을 채워 `results/gold_labels.csv`로 저장한다. 날짜와 결정 내역을 기록한다.

## 5. 팀이 결정할 사항 (SAP 확정 전)

1. **성공 기준 수치**: 초안은 kappa ≥ 0.70, 초가공 F1 ≥ 0.85, UPF% 오차 ≤ 3%p. 사람 간 kappa 보고치(0.75[4])를 참고해 정한다.
2. **정답셋 크기·구성**: 초안은 400개(상위 200 + 꼬리 200). 두 사람의 작업량(코드당 1-2분)과 CI 폭을 함께 고려한다.
3. **결정 규칙 D5-D8**: 소주·빵·개량 장류·즉석밥 등 애매한 식품의 기준. 바꾸면 `prompts.py`도 함께 바꾼다.
4. **LLM 입력 범위**: 초안은 식품명·식품군·제품명·제조사만 넣고 `대표_응답식품명`·`대표_음식명`은 뺐다. 넣으면 성능이 오를 수 있지만 "사전 정보만으로"라는 질문이 달라진다.
5. **few-shot 예시**: 초안의 12개를 그대로 쓸지, 팀 정답 규칙에 맞춰 다시 고를지(반드시 정답셋 밖 코드).
6. **14B 모델·임베딩 분류기 추가 여부**: 추가하면 탐색 분석으로 표기한다.
7. **분량**: 참고문헌 포함 2.5쪽 목표. 넘치면 표 2를 본문 문장으로 바꾼다.

## 6. 주의

- 원시자료 폴더(`질병청데이터/`)는 읽기만 한다.
- GPU는 `nvidia-smi`로 비어 있는 것만 쓴다. 다른 사용자의 작업이 있는 GPU는 쓰지 않는다.
- 심사용 원고에는 저자명·소속·이메일·사사를 넣지 않는다.
- "자동 분류가 사람을 대체한다"는 표현은 사전 기준을 모두 충족할 때만 쓴다.
